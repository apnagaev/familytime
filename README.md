# FamilyTime: время детей за компьютером (Keycloak + AD, Ansible + Docker Compose)

Родительский контроль для компьютеров в домене Active Directory с одним порталом управления.

- **Лимит по дням недели** и **свободное время по часам** (например, с 7:00 до 21:30) для каждого ребёнка
- **Учебные сайты и программы не тратят время** и продолжают работать, когда лимит кончился
- **Режим «только учёба»** после лимита: остальные окна закрываются, в Chrome, Edge и Яндекс Браузере открываются только учебные сайты
- **Сообщения меняются в портале**: предупреждение за 10 и 5 минут, «время закончилось», «вне свободного времени»
- **Портал**: родитель управляет лимитами и добавляет время, ребёнок видит свою статистику и может попросить ещё время
- **Несколько семей**: родитель видит только своих детей и компьютеры; настройки сайтов и программ — у каждого ребёнка свои, с копированием между детьми
- **Запрос времени приходит в Telegram** с кнопками «Дать» / «Отказать»
- **Статистика по программам и сайтам**: что сколько заняло, отдельно учёба; программы — понятными названиями («Ножницы», «Microsoft Word»)
- **Запрещённые сайты и программы** в любом режиме, **подписки на списки** по ссылкам с автообновлением, как в Pi-hole и AdGuard
- **Локация компьютеров** в Traccar: Wi-Fi вокруг + IP → Яндекс Локатор. Режим «потерян»: чаще точки, сообщение на весь экран, блокировка входа
- Агент ставится и на компьютеры взрослых: время у них не считается, только локация
- Вход в портал через Keycloak, роли из AD; сервер на двух узлах, состояние в PostgreSQL

```

   ┌──────────────────────────┐                    │ браузер
   │ служба FamilyTime (SYSTEM)│ https: пульс раз   │

   │  └ помощник в сеансе      ├──────────┐  ┌──────▼──────┐   ┌──────────┐
   │    (окна, адрес вкладки,  │          └─►│ reverse     │──►│ Keycloak │ вход, роли
   │     сообщения)            │             │ proxy, TLS  │   └──────────┘

                                          :8097 │       │ :8097
                                      ┌────────▼─┐   ┌─▼────────┐
                                      │ node1    │   │ node2    │  FastAPI
```

## Сервер

### 1. База

```sql
CREATE USER familytime WITH PASSWORD 'длинный-случайный-пароль';
CREATE DATABASE familytime OWNER familytime;
```
Таблицы создаются при старте. Разрешите вход с адресов узлов в `pg_hba.conf`, если нужно.

### 2. Keycloak

1. Clients → Create client `familytime` (OpenID Connect): Client authentication — вкл., Standard flow — вкл.
   - Valid redirect URIs: `https://kids.example.com/oidc/callback`
   - Valid post logout redirect URIs: `https://kids.example.com/*`
   - Web origins: `https://kids.example.com`
2. Credentials → Client secret → в `familytime_oidc_client_secret`.
3. Роли — **роли клиента** `familytime` (Clients → familytime → Roles), роли realm не учитываются:
   - `parent` — родитель: видит и настраивает детей и компьютеры своих семей;
   - `admin` — администратор: видит все семьи и компьютеры, создаёт семьи, назначает родителей, меняет общие настройки.

   Выдать: Users → пользователь → Role mapping → Assign role → Filter by clients → `familytime`. Можно группе AD: Groups → группа → Role mapping. Роли должны попадать в токен: в Client scopes у клиента оставьте стандартный `roles` (он добавляет `resource_access`).
4. Логин в портале берётся из `preferred_username` и для доменных пользователей должен совпадать с логином Windows (sAMAccountName). Если у вас в этом поле почта, поменяйте `familytime_oidc_username_claim` на атрибут с коротким именем.
5. Детям роли не нужны. Ребёнок видит свою страницу, если его логин Keycloak совпадает с логином в списке детей **или** его почта в Keycloak совпадает с почтой, указанной у ребёнка в портале, и подтверждена (Email verified). Второе — для детей на компьютерах вне домена: заведите им обычного пользователя Keycloak с почтой.

### 3. Traccar и Яндекс Локатор

- Ключ [API Яндекс Локатора](https://yandex.ru/maps-api/products/locator) → `familytime_yandex_locator_keys` (можно несколько через запятую: отклонённый ключ пропускается).
- `familytime_traccar_osmand_url` — порт протокола OsmAnd в Traccar (прямо в Traccar, не через прокси, который подменяет IP).
- `familytime_traccar_api_url` и `familytime_traccar_token` (Traccar → Настройки → пользователь → токен) — чтобы устройства создавались сами. Без них создайте устройства вручную: идентификатор — полное имя компьютера в нижнем регистре, например `kidlap.example.local`. Такой же идентификатор был у прежнего скрипта geotracking, поэтому история старых устройств продолжится.

**Как определяется место**, от дешёвого к дорогому:

1. **Известный адрес.** Общие настройки → «Известные адреса»: строки `IP-или-подсеть широта долгота [точность, м] [название]`. Компьютер пришёл с такого адреса — место берётся из таблицы, без запросов наружу. Подходят и внутренние подсети (дома компьютеры ходят на портал через локальную сеть), из пересекающихся выбирается самая узкая.
2. **Wi-Fi вокруг** → Яндекс Локатор. Пока пять самых сильных точек и IP те же, что в прошлый раз, прошлое место используется повторно до суток, без нового запроса.
3. **Без Wi-Fi** (настольный компьютер без адаптера) — по внешнему IP, с точностью до города: сначала Яндекс Локатор по IP, если он не знает — служба `familytime_geoip_url` (по умолчанию ip-api.com). Результат запоминается на неделю.

В Traccar точка уходит каждый раз, в том числе с повторно использованным местом, чтобы устройство оставалось на связи.

В точку пишутся: точность, заряд и питание, пользователь, `extip` — адрес, с которого компьютер пришёл на портал (дома это адрес в локальной сети), `localIP`, `wifiCount`, `session` (`active`/`locked`/`none`), `ignition` = кто-то работает за компьютером, `source` (`known-ip`, `yandex-wifi`, `yandex-ip` или `geoip`), `place` — название известного места или город, `alarm=lost` в режиме «потерян». `ip` не передаётся: его дописывает прокси перед Traccar. Параметры `wifi` и `cell` у Traccar зарезервированы под формат «MAC,сигнал», поэтому число точек Wi-Fi идёт как `wifiCount`.

### 4. Переменные и запуск

```bash
cp inventory.example.yml inventory.yml
cp vars/familytime.example.yml vars/familytime.yml     # заполнить, секреты: openssl rand -hex 32
ansible-vault encrypt vars/familytime.yml
ansible-playbook -i inventory.yml install_familytime.yaml --ask-vault-pass
```

Плейбук на каждом узле по очереди: правила nftables (порт открыт только `familytime_nodes` — узлам и vIP прокси, Docker-сетям и `trusted_nets`), исходники и `familytime.env` (`0600`), сборка образа, `docker compose up -d`, ожидание `/health`, удаление старых образов. Схему базы применяет первый стартовавший узел под advisory lock.

Telegram опрашивает один узел (advisory lock), второй подхватывает, если первый пропал.

### 5. Reverse proxy

Пример — `files/openresty/familytime.conf.example`: upstream на оба узла, `X-Real-IP` обязателен (по нему Яндекс определяет место без Wi-Fi), журнал запросов агентов отключён.

## Агент

### Сборка (Windows)

На любом компьютере с Python 3.12 x64:
```powershell
cd agent
.\build.ps1          # → dist\FamilyTime-1.0.0.zip
```
Или GitHub Actions (`.github/workflows/agent.yml`): тесты на Linux и сборка на `windows-latest`, архив — в артефактах прогона.

В архиве: папка `FamilyTime` (`familytime-agent.exe` — служба, `familytime-helper.exe` — помощник), `install.ps1`, `uninstall.ps1`, `familytime.example.json`.

### Установка через GPO

1. Общая папка, например `\\server\familytime$`: чтение для **Domain Computers** и администраторов, без доступа пользователям (там секрет регистрации). Распакуйте туда архив и создайте `familytime.json`:
   ```json
   { "server_url": "https://kids.example.com", "enroll_secret": "…", "mode": "control" }
   ```
2. GPO на OU с компьютерами: Конфигурация компьютера → Политики → Конфигурация Windows → Сценарии → **Автозагрузка** → PowerShell: `\\server\familytime$\install.ps1`.
3. При каждой загрузке сценарий сравнивает версию и настройки и ничего не делает, если всё совпадает. Обновление — положить новую папку `FamilyTime` в общую папку.

Вручную (от администратора): `.\install.ps1 -ServerUrl https://kids.example.com -EnrollSecret … `.

Что делает установка: файлы в `C:\Program Files\FamilyTime` (пользователи только читают), настройки в `C:\ProgramData\FamilyTime` (только SYSTEM и администраторы), служба `FamilyTime` (автозапуск, перезапуск при сбое), разрешение на местоположение для списка Wi-Fi (Windows 11 24H2).

Компьютер появляется в портале на странице «Компьютеры» после первого выхода на связь. `mode` при установке: `control` (по умолчанию, подходит везде: время считается только у учётных записей из списка детей) или `track` — только локация; потом режим меняется в портале.

### Обязательные настройки домена

| Что | Где | Зачем |
|---|---|---|
| Дети — не локальные администраторы | Restricted Groups / «Группы с ограниченным доступом» | иначе службу можно остановить |
| Блокировка экрана при простое | Конфигурация компьютера → Параметры безопасности → «Интерактивный вход: порог бездействия компьютера» = 900 | заблокированный компьютер время не тратит |
| Местоположение не выключено | Компоненты Windows → Расположение и датчики → «Отключить расположение» = Отключено | список Wi-Fi для Яндекс Локатора |
| Политики URLBlocklist / URLAllowlist браузеров не задаются на уровне компьютера | GPO Chrome, Edge, Яндекс | политики компьютера важнее политик пользователя, которые ставит агент |
| BitLocker, пароль BIOS, запрет загрузки с USB | — | без этого вор просто переустановит Windows |

Другие браузеры (Firefox, Opera и т. п.) агент закрывает сам — список «Запрещены всегда» в настройках портала. Дополнительно их можно запретить политикой ограниченного использования программ.

Старый скрипт geotracking в планировщике снимите: локацию теперь отправляет агент.

## Семьи, роли и настройки ребёнка

- **Семья** — несколько родителей и несколько детей. Все родители семьи видят всех её детей, их запросы и компьютеры семьи; чужих не видят и не могут ими управлять (чужая страница отвечает «не найдено»).
- Семью создаёт администратор (страница «Семьи») или она создаётся сама, когда родитель без семьи добавляет первого ребёнка. Второго родителя добавляет любой родитель семьи по его логину Keycloak. Логин, уже занятый ребёнком другой семьи, добавить нельзя.
- **Компьютер** привязывается к семье, когда на нём впервые входит ребёнок этой семьи, либо вручную администратором. Компьютеры без семьи (например, взрослые с режимом «только локация») видит только администратор.
- **Настройки ребёнка** (страница ребёнка): лимиты по дням, сайты, программы, протоколы, подписки на списки, порог простоя и предупреждения, почта для входа в портал, дополнительные логины Windows. Кнопка «Скопировать настройки другим детям» переносит сайты, программы, протоколы, простой, предупреждения и подписки; лимиты, почта и логины не копируются.
- **Настройки семьи** (страница «Семья»): тексты сообщений и чаты Telegram для запросов времени. Запрос ребёнка приходит только в чаты его семьи (и в общие `familytime_telegram_chat_ids`, если заданы — это чаты администратора), решить его может только чат, которому он пришёл.
- **Общие настройки** (только администратор): интервалы локации и сообщение на потерянном компьютере.
- **Ребёнок на компьютере вне домена:** в «Дополнительные логины Windows» впишите имя его локальной или Microsoft-учётной записи (как его показывает страница «Компьютеры») — время пойдёт в общий лимит; в «Почта для входа в портал» — почту его пользователя Keycloak.

### Переход с версии 1.1

При первом запуске 1.2 сервер сам: создаёт семью «Семья» и помещает в неё всех существующих детей и компьютеры; общие списки сайтов и программ, простой и предупреждения копирует каждому ребёнку; общие подписки раздаёт каждому ребёнку; тексты сообщений переносит в семью. После обновления:

1. В Keycloak создайте роли клиента `parent` и `admin` и выдайте их (роль realm `familytime-parent` больше не действует). В `vars/familytime.yml` поставьте `familytime_oidc_parent_role: parent`, `familytime_oidc_admin_role: admin`.
2. Войдите администратором, на странице «Семьи» переименуйте семью и добавьте родителей по логинам.
3. Обновите агенты до 1.2. Агенты 1.1 продолжают работать, но получают один набор списков на компьютер — объединение по детям семьи компьютера; правила «по ребёнку» действуют с агентом 1.2.

## Списки сайтов и программ

Страница ребёнка → «Сайты, программы и протоколы» и «Подписки на списки». У каждого ребёнка свои четыре списка: учебные сайты, запрещённые сайты, учебные программы, запрещённые программы. Итог каждого = ручные записи + все включённые подписки, ручные идут первыми.

- **Форматы подписок:** hosts (`0.0.0.0 example.com`), AdGuard/uBlock (`||example.com^`, `||example.com^$important`), простой список доменов по строке; для программ — имена `.exe` по строке. Исключения `@@`, маски, регулярные выражения и правила с путями или модификаторами (`$client=` и т. п.) пропускаются: FamilyTime блокирует домены целиком, с поддоменами.
- **Обновление:** у каждой подписки свой интервал (по умолчанию 24 ч). Обновляет один узел (advisory lock), с `If-None-Match`/`If-Modified-Since`: неизменённый список заново не качается. Кнопка ↻ — обновить сейчас. Ошибка загрузки видна в таблице, прежние записи при этом остаются.
- **Доставка на компьютеры:** в пульсе агент получает версию списков вошедшего ребёнка, а сами списки забирает отдельно, когда версия поменялась, и хранит по детям в `C:\ProgramData\FamilyTime\lists.json`. Агенты 1.1 получают один набор на компьютер (объединение по детям семьи), агенты 1.0.x — его же в каждом пульсе, урезанный до 5000 записей.
- **Запрещённый сайт** в учебные не попадает, даже если есть в учебной подписке.
- **Разрешённые протоколы** (`telemost`, `zoommtg`, `msteams` по умолчанию) — ссылки вида `telemost://…`, через которые сайт открывает программу («Открыть в приложении»). В режиме «только учёба» без этого браузер их блокирует. Саму программу добавьте в учебные, иначе её окно закроется.
- **Лимит браузеров:** политики Chrome, Edge и Яндекса принимают до 1000 адресов. В `URLBlocklist` уходят первые 1000 запрещённых, остальные агент ловит по адресу активной вкладки и закрывает её (Ctrl+W). В режиме «только учёба» открываются первые 1000 учебных сайтов.
- Запреты действуют на детей. Для блокировки на всю сеть, всем устройствам, теми же списками лучше подходит AdGuard Home на уровне DNS.

## Как это работает

**Что считается.** Время идёт, пока сеанс ребёнка активен и не заблокирован. Простой дольше заданного (по умолчанию 15 минут) не считается, если на экране нет полноэкранного окна: фильм или игра на весь экран считаются всегда. Учебная программа или учебный сайт в активной вкладке — время не списывается, идёт в «учёбу». Сайт определяется по адресной строке активного окна браузера (UI Automation), расширение не нужно.

**Несколько компьютеров** у одного ребёнка складываются: лимит общий.

**Кто считается ребёнком** — только учётные записи из списка детей (логин или один из дополнительных логинов Windows). На них действуют, даже при лимите «без ограничений», запрещённые сайты и программы, выключенные инкогнито и гостевой режим браузеров, сбор статистики. Взрослых в список не добавляйте: если учётную запись убрать из списка или выключить ей контроль, агент сам снимет с неё политики браузеров (с версии агента 1.1.1).

**Лимит или вне свободного времени** → режим «только учёба»:
- окно с текстом из портала и кнопкой «Попросить ещё время»;
- браузеры один раз закрываются, при следующем запуске в них открываются только учебные сайты, портал и Keycloak (политики `URLBlocklist`/`URLAllowlist` в разделе реестра ребёнка, плюс выключены инкогнито и гостевой режим);
- окна остальных программ закрываются (вежливо, через 10 с — принудительно); лаунчеры и мессенджеры из списка закрываются даже без окна;
- если помощник убит или завис, служба перезапускает его, а в режиме «только учёба» через 45 с без помощника завершает сеанс.

Родитель добавил время (в портале или кнопкой в Telegram) — в течение минуты всё возвращается.

**Без связи с сервером** агент продолжает считать по последней политике и правилам недели (бонусы на новый день не переносятся), а когда связь появляется, отправляет накопленное. Повтор пакета не засчитывается дважды: у пакетов есть номер.

**Часы компьютера** в расчёт не берутся: агент живёт по времени сервера.

**Режим «потерян»** (страница «Компьютеры»): точки раз в 2 минуты, сообщение на весь экран поверх всего, «блокировать вход» — любой сеанс сразу завершается. Работает только если компьютер выходит в интернет: до входа пользователя ноутбук подключается лишь к знакомым сетям.

## Проверка

```bash
curl -s http://127.0.0.1:8097/health                   # {"ok":true,...}
docker logs familytime 2>&1 | tail
nft list table inet familytime
```
На компьютере: служба `FamilyTime` работает, журнал `C:\ProgramData\FamilyTime\logs\agent.log`, журнал помощника `%LOCALAPPDATA%\FamilyTime\helper.log`. Отладка от администратора: остановить службу и запустить `"C:\Program Files\FamilyTime\familytime-agent.exe" console`.

## Обновление

- Сервер: поменять `familytime_version`, прогнать плейбук.
- Агент: новая версия в `agent/familytime_agent/__init__.py`, сборка, папка `FamilyTime` в общую папку. Компьютеры обновятся при следующей загрузке.

## Удаление агента

`uninstall.ps1` от администратора: служба, файлы и политики браузеров во всех профилях (иначе браузер ребёнка останется в режиме «только учёба»).

## Диагностика

**Компьютера нет в портале.** `C:\ProgramData\FamilyTime-install.log` и `agent.log`: «регистрация не удалась» — неверный `enroll_secret` или сервер недоступен.

**Помощник постоянно перезапускается** (в `agent.log` раз в минуту «помощник … не отвечает — перезапуск»). Причина — в `%LOCALAPPDATA%\FamilyTime\helper.log` пользователя: строка «нет связи со службой». Без помощника работает только локация, а в режиме «только учёба» сеанс завершается.

Журналы в UTF-8: в Windows PowerShell 5 читайте их через `Get-Content … -Encoding UTF8`, иначе русский текст превращается в «кракозябры».

`familytime-agent.exe console` (от администратора) не умеет запускать помощника: ошибка `WTSQueryUserToken 1314` в этом режиме нормальна, это может только служба.

**Время не считается.** Логин ребёнка в портале должен совпадать с логином Windows без домена. В `agent.log` — нет ли «нет связи с сервером».

**Сайт не определяется** (вся работа в браузере уходит в «chrome.exe»). Проверьте `helper.log`: «UI Automation недоступна». Адрес читается из адресной строки; если окно браузера свёрнуто в киоск-режим или строки нет, сайт не определится.

**Учебный сайт ломается в режиме «только учёба»** (не грузится вход, видео). Он тянет страницы с других доменов: добавьте их в «Учебные сайты» или `familytime_extra_allowed_domains`.

**Нет локации.** В портале на странице компьютера нет места: проверьте ключ Локатора (`docker logs familytime | grep locator`) и что в Windows включено местоположение. На Windows 11 24H2 без разрешения список Wi-Fi пуст, тогда место определяется только по IP (точность — город).

**Страница грузится долго.** Firewall: `nft delete table inet familytime` (вернуть: `nft -f /etc/nftables.d/familytime.nft`).

## Ограничения

- Считается только интерактивный сеанс на экране компьютера; RDP-сеансы не учитываются.
- Сайт определяется только в Chrome, Edge и Яндекс Браузере. Политики Яндекс Браузера пишутся под оба набора имён (`URLBlocklist`/`URLBlacklist`), но их поддержку в домашней версии стоит проверить на своём компьютере.
- Окна приложений из Microsoft Store принадлежат `ApplicationFrameHost.exe`. Помощник находит настоящий процесс приложения: в статистике оно видно под своим именем, а в режиме «только учёба» закрывается принудительно через 10 секунд, без вежливого WM_CLOSE.
- Закрытие вкладки с запрещённым сайтом сверх лимита политики — нажатием Ctrl+W в активном окне. Если ребёнок переключится в момент нажатия, закроется вкладка, которая стала активной; помощник проверяет окно и адрес перед нажатием.
- Ребёнок может держать учебный сайт активной вкладкой и слушать видео в фоне — время уйдёт в «учёбу». Это видно в статистике по сайтам.
